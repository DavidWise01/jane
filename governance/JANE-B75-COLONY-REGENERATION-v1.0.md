## Regeneration invariant
Replacing a worker creates a NEW identity and preserves the predecessor's history. Jane's authority does not depend on any subordinate staying alive, reporting or completing work. A worker is never silently resurrected as the same actor.

## Lifecycle
OBSERVE LOSS -> RETIRE old identity -> CREATE successor (new immutable ID) -> optional assign delegated role/scope -> APPEND event. These steps are Jane-side decisions and do not await the lost agent. There is no quorum.
Worker genealogy: successor.parent_id identifies a predecessor, but successor is not the predecessor. Failed workers cannot reuse their original capability grants. Every successor starts with no external permissions; a separate grant is required.
Bounded resources: simulated capacity and budget limits do not redefine governance. Jane can shrink the colony or run with zero workers without losing her architectural role.
The ephemeral task trail may be inherited as context only, never as permission or evidence of success. Append-only provenance preserves deaths, retirements and births.
Four registers [[ a(self) :: b([i]) :: c([id]) :: d[(sid)] ]].
Human-root halt and platform permissions remain absolute external gates.

## Acceptance
1. Simulated lost worker remains retired.
2. Replacement has a unique ID and points back to predecessor.
3. History is not overwritten.
4. Replacement has no inherited credentials.
5. Jane can regenerate, refuse regeneration, or recall all without agent vote/completion.
6. Active count never exceeds set simulation cap.
7. Browser-only simulation must not claim actual spawning or durable memory.
