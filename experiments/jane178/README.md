# JANE 178 — The Authority That Must Be Delegated

**Invariant:** Every delegated grant must be a subset of its issuer's active authority, with no additional scope, longer lifetime, or greater delegation depth.

The executable `delegation.py` uses Ed25519-signed grants, canonical JSON, persistent SQLite grant/nonces/revocations, recursive predecessor verification, cycle rejection and a local hash-linked audit record. Revoking a parent disables the descendant chain at or after the effective revocation timestamp. The original signed grants remain preserved. No delegation automatically activates an experiment, changes Jane's active parent, or creates independent witness votes.

Run: `python -m unittest -q test_delegation.py`; expected **45 passing tests**. Run `python delegation.py` for a demonstration. The result JSON is generated by this exact demonstration.

**Boundary:** Configured public keys and all people/organizations are *synthetic fixtures*. Valid signatures attest to key possession, not real-world institutional authority. This model trusts its originally installed root and key directory; it does not check a physical operator's identity, secure key custody, external revocation distribution or whether historic timestamp claims reflect actual clocks. Local hash-linked records need external head retention to detect clean truncation. Revocation uses a single signed issuer command and does not implement multi-party appeals, recovery or retroactive nullification.

## Next natural bound — JANE 179
Delegation conflict and key compromise: a legitimate grant and a forged-looking but validly signed grant can coexist when a steward's secret key is compromised. FLAY must separate signature validity from root-of-trust recovery, record verified compromise events and define non-retroactive reissuance.
